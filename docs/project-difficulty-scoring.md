# 项目难度评分方式

本文定义大屏中节点、阶段和项目整体难度的计算口径，用于项目质量评估与后续 AI 分析。

## 难度层级

节点难度由项目人员在节点详情中配置：

| 难度 | 基础分 |
| --- | ---: |
| 低难度 `low` | 25 |
| 中等 `medium` | 50 |
| 困难 `high` | 75 |
| 特别困难 `critical` | 100 |

阶段和项目难度不手工填写，按综合评分自动计算。

## 阶段评分

阶段评分以其下任务节点为输入。每个节点按工作量加权，工作量优先使用预估工时；没有工时时使用任务项次数量；仍为空时按 `1` 计算。

```text
阶段基础分 = Σ(节点难度基础分 × 节点工作量占比)
```

在基础分上增加风险放大项：

```text
阶段难度分 =
  阶段基础分
+ 关键路径工作量占比 × 10
+ 风险暴露工作量占比 × 10
+ 阻塞工作量占比 × 10
```

风险暴露按风险等级折算：

| 风险等级 | 暴露系数 |
| --- | ---: |
| 低风险 | 0.2 |
| 中风险 | 0.6 |
| 高风险 | 1.0 |

## 项目评分

项目评分以阶段为输入，阶段工作量为该阶段节点工作量总和。

```text
项目基础分 = Σ(阶段难度分 × 阶段工作量占比)
项目难度分 =
  项目基础分
+ 含关键路径阶段工作量占比 × 10
+ 阶段风险暴露占比 × 10
+ 含阻塞阶段工作量占比 × 10
```

## 分数映射

阶段和项目统一使用以下分段：

| 分数 | 难度 |
| --- | --- |
| `0-39` | 低难度 |
| `40-59` | 中等 |
| `60-79` | 困难 |
| `80-100` | 特别困难 |

## 设计原则

- 一个高工作量的困难节点，应比多个低工作量简单节点更影响阶段判断。
- 关键路径、风险和阻塞不会替代难度基础分，只作为放大项体现交付不确定性。
- 任务项次进度只影响完成度和时间跨度；节点难度由项目人员配置，阶段和项目难度由系统计算。
